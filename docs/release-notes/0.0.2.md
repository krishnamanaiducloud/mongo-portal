# mongo-portal 0.0.2

## Highlights

- **OpenID Connect sign-in** with Microsoft Entra ID, Okta, Keycloak or any
  corporate provider (SAML and LDAP through a broker): authorization code
  flow with PKCE, state and nonce; ID tokens verified against the provider's
  keys (issuer, audience, authorized party, expiry). Several providers can be
  configured; each is passive like OpenShift login.
- **MONGODB-OIDC**: connect to MongoDB Enterprise with your corporate
  identity. The portal signs you in at the identity provider the database
  trusts and hands MongoDB your own token; it checks that the server expects
  that provider before sending a token, refreshes tokens on expiry and keeps
  them only in memory. SCRAM keeps working alongside.
- **Import and export**: Extended JSON (relaxed or canonical), JSON arrays,
  CSV/TSV with field mapping and types, BSON and gzip. Exports stream from
  MongoDB; database exports are zip archives with collection metadata and a
  manifest with SHA-256 checksums. Imports run in the background with
  preview, dry run, upsert, progress, cancellation and per-record errors.
- **Operations**: running operations and idle connections with filters and
  paging; end an operation with `killOp` after typed confirmation (MongoDB
  authorizes it).
- **Monitoring**: oplog window, last election, latency, CPU, page faults,
  lock waits, evictions, execution tickets, failed authentications, database
  statistics, index usage and alerts with configurable thresholds.
- **Audit**: event ids, trace ids, method, client, duration and counts; a
  per-replica hash chain with verification; optional durable store with
  retention; search by user, action, outcome, namespace and time; CSV and
  NDJSON export.
- **Sessions**: optional shared registry to list and revoke sessions of
  every replica, or every session of a user.
- **RBAC**: new resources (export, import, monitoring, operations, sessions,
  settings), new roles (`role:dbadmin`, `role:monitoring`, `role:auditor`,
  `role:platform-admin` without data access) and rules scoped to
  connection profiles. Every denial is audited.
- **UI**: dashboard, import and export, operations, audit search, session
  administration, settings; the shell gets a Run button, saved snippets,
  searchable history, diagnostics templates, table and JSON views, result
  downloads and an explain summary.
- **OpenTelemetry**: OTLP over HTTP or gRPC, TLS, headers, sampling and
  resource attributes; logs carry trace ids.
- **OpenShift**: pod name for the audit chain, an emptyDir for imports,
  optional OIDC and store secrets, zone spread, optional autoscaling and OTLP
  egress components.

## Upgrade notes

- Everything new is optional and off by default except import/export (on;
  `transfer.enabled: false` turns it off) and the new built-in roles.
- `role:readonly` now includes export and monitoring; `role:editor` includes
  import. Review custom policies that relied on the previous scope.
- The monitoring API checks the `monitoring` resource instead of `server`.
  Custom roles with only `server get` need `monitoring get` as well.
- Mount the new `transfer` emptyDir (included in the manifests) before
  enabling large imports; `/tmp` stays a small in-memory volume.
- Database home is now **Dashboard**; the database list moved to
  `/databases`.

## Known limitations

- Sessions stay on the replica that created them; when it stops, users
  connect to MongoDB again. The registry gives visibility and revocation, not
  failover.
- OIDC sign-ins are not re-checked at the provider during their lifetime.
- SAML 2.0 and LDAP are supported only through an OIDC broker.
- Per-user X.509 login is not offered (the profile's client certificate is
  used for TLS and for the store connection).
- Exports are not point-in-time backups.
- The cluster-side MongoDB Enterprise OIDC configuration was validated with
  a disposable MongoDB Enterprise 7.0 server and a test identity provider,
  not with the production deployment or identity provider.
