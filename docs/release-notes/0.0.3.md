# mongo-portal 0.0.3

## Highlights

- **One sign-in for portal and MongoDB.** Profiles with MONGODB-OIDC can set
  `oidc.autoConnect`: after OpenShift or OIDC sign-in the portal connects
  the user to MongoDB with a silent authorization request (`prompt=none`) at
  the identity provider MongoDB trusts. When OpenShift federates to the same
  provider, there is no password and no second prompt; MongoDB still receives
  only the user's own token and enforces that user's roles. If the provider
  needs the user, the portal continues with its sign-in page
  (`interactiveFallback`), and never falls back to a password.
- **Precise MONGODB-OIDC errors.** Opaque access tokens, tokens from another
  issuer (for example Entra ID v1) or for another audience
  (`oidc.audience`) are explained before the token reaches MongoDB.
  `oidc.authParams` passes provider-specific parameters such as `audience`.
- **Read-only preflight.** `mongo-portal preflight` checks DNS, network, TLS
  (verification, host name, expiry), topology and version, sign-in
  providers, the store account's privileges and, for MONGODB-OIDC, which
  issuer and client id the server announces — without sending a token or
  writing anything. The same checks run as **Diagnose connection** in the UI,
  as `helm test`, and from `scripts/preflight-openshift.sh`, which also
  inspects the deployment with read-only `oc` calls.
- **Configuration placeholders.** `${NAME}` and `${NAME:-default}` in any
  configuration value; unset variables fail by name. One configuration
  serves every organization and environment.
- **Helm chart** for OpenShift (Route, service CA, OAuth client, optional
  SCC) and Kubernetes (Ingress), with a values schema, NetworkPolicies, PDB,
  HPA, ServiceMonitor and a preflight test. No defaults name an
  organization, registry account or host.
- **Cache management.** Administrators see the portal's own caches and
  invalidate them on one or every replica (typed confirmation, audited,
  results per replica). Everyone gets **Refresh & connection**: refresh
  data, the database list or the connection status, reconnect to MongoDB,
  clear personal UI data.
- **No false slow-operation alerts.** Awaitable `hello` from driver
  monitoring, change streams, tailable cursors and oplog tailing are shown as
  expected waits; `monitoring.slowOperationIgnoreApps` covers agents.
- **Modernized UI.** Two-step sign-in (portal sign-in, then database
  connection) with clear separation of the two, refreshed visual design in
  light and dark themes, navigation icons, page headers. The UI and the
  public API no longer show the build version or commit.

## Fixes

- With the documented store grant (`readWrite`), changing `audit.retention`
  made the store unavailable (the TTL change needs `collMod`). The store now
  stays usable and logs what the database administrator must apply.
- Zero timestamps were shown as "1/1/1" for providers never checked.
- CI guardrails: two of the three manifest guardrail checks could never fail
  the job.
- A CI test flake: the OpenShift login unit test's request timeout under the
  race detector.

## Upgrade notes

- Configuration values containing `${` are now placeholders; write `$${` for
  a literal `${`.
- `/api/v1/me`, `/api/v1/status` and `/api/v1/settings` no longer include
  `build`. The version is available from `mongo-portal --version` and the
  `mongo_portal_build_info` metric.
- New RBAC resource `cache` (`get`, `delete`), granted to
  `role:platform-admin` (and `role:admin`).
- CI publishing reads the image and registry from repository variables
  (`CONTAINER_IMAGE`, `CONTAINER_REGISTRY`, `RELEASE_ENVIRONMENT`) and the
  secrets `CONTAINER_REGISTRY_USERNAME` / `CONTAINER_REGISTRY_TOKEN`; without
  `CONTAINER_IMAGE` nothing is published.

## Known limitations

- Not validated against a live OpenShift cluster, a production identity
  provider or the target MongoDB Enterprise deployment; see the testing
  report for what was tested where.
- MongoDB sessions stay on the replica that opened them; after a restart
  users reconnect (silently with `autoConnect`).
- GO-2026-5932 (x/crypto/openpgp) is reported by Trivy at module level; the
  packages are not in the binary (VEX statement in `security/vex`).
