# mongo-portal 0.0.4

## Highlights

- **Performance advisor.** A new page recommends indexes and constraints:
  full collection scans with an index suggestion in Equality-Sort-Range
  order, unselective indexes, in-memory sorts, redundant and unused indexes,
  many indexes, large documents, large collections without secondary
  indexes, and collections without constraints (unique indexes, schema
  validation). It reads index definitions and usage, collection statistics,
  the profiler and the slow-query log with the user's own MongoDB session,
  changes nothing, shows queries only as shapes (every value replaced by
  `?`) and never runs its suggestions. See
  [performance-advisor.md](../performance-advisor.md).
- **Cache management follows MongoDB under `role:mongodb`.** Users whose
  MongoDB account administers the deployment (root, clusterAdmin,
  userAdminAnyDatabase, or custom roles with the same cluster privileges)
  now see and use **Caches** without an RBAC mapping. All-database data
  roles do not qualify; explicit deny rules still apply.

## Upgrade notes

- No configuration change is needed. The advisor appears for roles with
  `monitoring get`; it is most useful where a database administrator enabled
  the profiler for slow operations.

## Known limitations

- Unused-index findings rely on `$indexStats` of the member that answered;
  usage counters reset when a member restarts.
- The advisor reads at most 50 databases and 300 collections per run.
- Not validated against a live OpenShift cluster, production identity
  provider or the target MongoDB deployment (see the testing report).
